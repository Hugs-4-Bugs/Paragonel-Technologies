
# Paragonel Website

## About This Project

This is the official website for Paragonel, an innovative IT company focused on delivering cutting-edge solutions in AI (Artificial Intelligence), Cloud Computing, DevOps, and SaaS Platforms. The website aims to showcase the company's expertise, services, portfolio, and vision, providing a sleek, ultra-modern, and professional online presence.

## Core Features

*   **Sticky Navigation Bar**: Easy access to all main sections, with a responsive burger menu for mobile/tablet. Includes Home, About, Services, Portfolio, Team, Careers, Blog, Testimonials, FAQ, Contact. Login and Signup options are also integrated.
*   **Dynamic Hero Section**: Featuring the company tagline "Shaping the Future for Tomorrow" with an animated gradient background and distinct styling for slogan and description.
*   **Comprehensive Sections**:
    *   **About Us**: Mission, vision, company story, and values presented with a timeline/infographic format.
    *   **Services**: Overview section linking to detailed individual pages for AI Solutions, Cloud Infrastructure, DevOps Automation, and SaaS Platforms.
    *   **Portfolio**: Carousel showcasing successful projects with mockups/previews.
    *   **Team**: Clean profile cards for team members, including the Founder & CEO (Prabhat Kumar). Clicking a card opens a modal with a detailed bio and social links.
    *   **Careers**:
        *   Interactive job board initially hidden, toggled by a "View Open Roles" button.
        *   Advanced filtering by Location, Department, Job ID, Employment Type, Date Posted, and Work Arrangement (Remote/Onsite).
        *   Job cards display key information. Clicking a job card opens a modal with the full job description.
        *   "Apply Now" button on job cards opens a detailed job application form within a modal. This form includes:
            *   Personal Information (Name, Email, Phone, LinkedIn, Portfolio, Coding Profile URL).
            *   Resume Upload (PDF/DOCX, max 5MB).
            *   Education Details (Highest Qualification, Specialization, University, Passing Year, Marks/CGPA).
            *   Skills (Primary, Secondary).
            *   Work Experience (conditional fields for experienced candidates including company, title, duration, responsibilities; fresher option available).
            *   Additional Inputs (Cover Letter, Preferred Location, Current & Expected CTC, Notice Period).
            *   Mandatory policy acceptance and optional job notification opt-in.
        *   Application details are formatted by an AI flow for simulated email notifications to admin (`erprabhat72@gmail.com`) and a confirmation to the applicant.
    *   **Blog**: Listing of articles with links to individual detail pages for full content.
    *   **Testimonials**: Client success stories presented in a smooth, interactive slider.
    *   **FAQ**: Accordion-style question and answer section for common queries.
    *   **Contact**: Form for inquiries and detailed company contact information.
*   **AI-Powered Chat Assistant**: A globally accessible chat widget, powered by Genkit, that opens automatically on page load. It answers user questions about Paragonel, its services, careers, and provides links (e.g., to the company's LinkedIn profile) in a clickable format.
*   **AI Content Curation**:
    *   **Personalized Recommendations**: The homepage features a section suggesting relevant articles or case studies based on simulated user behavior (e.g., viewed job titles), powered by a Genkit flow.
    *   **Dynamic Tech News**: The homepage includes a section that fetches and displays plausible recent tech news headlines and summaries related to AI, Cloud, DevOps, and SaaS, generated by a Genkit flow.
*   **User Authentication UI & Simulated Flow**:
    *   Frontend forms for Login, Signup, Forgot Password, and Reset Password using ShadCN UI and `react-hook-form`.
    *   The **Signup process** includes a simulated email OTP verification UI flow before registration can be completed. Password complexity rules are enforced with user feedback.
    *   **Simulated Login/Signup**: Uses client-side state (`AuthContext`) and `localStorage` for basic session persistence. Successful signup attempts to auto-login the user.
    *   **Protected Job Application**: The job application process is protected. Non-logged-in users attempting to apply for a job are redirected to the login page. After successful login/signup, they are redirected back, if appropriate.
*   **Newsletter Subscription**: Integrated into the footer for users to subscribe to updates.
*   **Cookie Consent System**:
    *   A banner appears on first visit with "Accept All," "Reject Non-Essential," and "Customize Settings" options.
    *   The "Customize" option opens a settings panel allowing users to toggle preferences for Functional, Performance, Analytics, and Marketing cookies (Essential cookies are always active).
    *   User preferences are stored in `localStorage`.
    *   Theme persistence (dark/light mode) is linked to "Functional Cookies" consent.
    *   Simulated loading of conditional scripts (analytics, marketing) based on consent is logged to the console.
    *   A link in the footer allows users to reopen and modify their cookie settings at any time.
*   **Visual Design & UX**:
    *   Sleek, ultra-modern aesthetic with a professional feel.
    *   Dark/Light theme toggle with persistence based on cookie consent.
    *   Subtle animations on scroll (`ScrollFadeIn`) and hover effects.
    *   Neon glow accents on icons.
    *   Fully responsive design for desktop, tablet, and mobile devices, ensuring a consistent and optimized experience.

## Getting Started (Local Development on macOS)

Follow these instructions to set up and run the project on your local machine.

### Prerequisites

*   **Node.js**: It's recommended to use a Node Version Manager like `nvm` to install and manage Node.js versions. This project is built with a recent LTS version (e.g., Node.js 20.x or later).
    ```bash
    # Install nvm (if you haven't already)
    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
    # Install Node.js (e.g., latest LTS)
    nvm install --lts
    nvm use --lts
    ```
*   **Package Manager**: `npm` (comes with Node.js), `yarn`, or `pnpm`. This project uses `npm` by default as per `package.json` scripts.
*   **Firebase CLI** (Required for Firebase deployment):
    ```bash
    npm install -g firebase-tools
    # or
    # yarn global add firebase-tools
    ```
    After installation, log in: `firebase login`.

### 1. Clone the Repository

If you haven't already, clone the project to your local machine:
```bash
git clone <your-repository-url>
cd <project-directory-name> # Should be 'quantumfusion-solutions-website' or similar
```

### 2. Install Dependencies

Install the project dependencies using npm:
```bash
npm install
```
If you prefer yarn or pnpm:
```bash
# yarn install
# pnpm install
```

### 3. Environment Variables

The Genkit AI features require a Google AI API key.

1.  Create a `.env` file in the root of your project (this file is usually gitignored).
    ```bash
    touch .env
    ```
2.  Add your Google AI API key to the `.env` file:
    ```
    GOOGLE_API_KEY="YOUR_GOOGLE_AI_API_KEY"
    ```
    *   **To get a Google AI API Key**: Visit [Google AI Studio](https://aistudio.google.com/app/apikey) and create an API key.

### 4. Run the Development Servers

This project requires two separate development servers to run concurrently: one for the Next.js application and one for the Genkit AI flows.

*   **Terminal 1: Start the Next.js Application**
    ```bash
    npm run dev
    ```
    This will typically start the Next.js app on `http://localhost:9002` (as configured in `package.json`).

*   **Terminal 2: Start the Genkit Development Server**
    ```bash
    npm run genkit:dev
    ```
    Alternatively, for auto-reloading of Genkit flows on change:
    ```bash
    npm run genkit:watch
    ```
    This will typically start the Genkit Developer UI on `http://localhost:4000`, where you can inspect and test your AI flows.

### Accessing the App

*   **Website**: Open your browser and navigate to `http://localhost:9002`.
*   **Genkit Developer UI**: Open `http://localhost:4000` to monitor and test AI flows.

## Deployment

You can deploy this Next.js application to various hosting platforms. All listed platforms have free tiers suitable for personal projects or low-traffic sites.

### General Configuration for Deployment

*   **Environment Variables**: Ensure that the `GOOGLE_API_KEY` (and any other necessary environment variables) is set up in your deployment platform's environment variable settings.
*   **Build Command**: The standard build command is `npm run build` or `next build`.
*   **Output Directory**: For Next.js, this is typically `.next`.

### Deploying to Vercel (Recommended for Next.js)

Vercel is highly recommended for Next.js projects as it's developed by the creators of Next.js.
1.  Connect your Git repository to Vercel.
2.  Vercel usually auto-detects Next.js projects.
    *   **Framework Preset**: Should be "Next.js".
    *   **Build Command**: `npm run build` (or `next build`).
    *   **Output Directory**: Should be automatically configured.
3.  Configure your `GOOGLE_API_KEY` in the Vercel project settings (Environment Variables).
4.  Deploy. Vercel handles Next.js features like Server Components and API Routes (used by Genkit's Next.js plugin) automatically.

### Deploying to Netlify

1.  Connect your Git repository to Netlify.
2.  Configure the build settings:
    *   **Build command**: `npm run build` (or `next build`).
    *   **Publish directory**: `.next`.
3.  Configure your `GOOGLE_API_KEY` in Netlify's site settings (Build & deploy > Environment > Environment variables).
4.  Netlify's Next.js runtime should handle the necessary configurations for deploying Next.js apps, including API routes that Genkit might use.

### Deploying to Firebase

Firebase can host Next.js applications, leveraging Firebase Hosting for static assets and Cloud Run for the Next.js server-side rendering and Genkit flows.

1.  **Firebase Project**: Ensure you have a Firebase project created at [Firebase Console](https://console.firebase.google.com/).
2.  **Initialize Firebase**: In your project root, run:
    ```bash
    firebase init hosting
    ```
    *   When prompted, select "Use an existing project" and choose your Firebase project.
    *   When asked "What do you want to use as your public directory?", Next.js apps usually output to `.next`, but Firebase's framework-aware CLI handles this. If prompted specifically for framework support for Next.js, select it. It might suggest "web frameworks" or similar.
    *   It will likely detect you're using Next.js and ask if you want to set up deploys to Cloud Run. Say **yes**. This is crucial for server-side features.
    *   Choose your preferred region for the Cloud Run service.
    *   It may ask to overwrite existing `firebase.json` or `.firebaserc` if you're re-initializing. Be cautious if you have custom configurations.
    *   The CLI should generate/update `firebase.json` to include a `frameworksBackend` section (for Cloud Run) and configure hosting rewrites.

3.  **Set Environment Variables for Backend (Cloud Run)**:
    Your Genkit flows need the `GOOGLE_API_KEY`. This needs to be set for the Cloud Run service that Firebase creates.
    *   You can set this via the Google Cloud Console: Go to your Cloud Run service, edit the revision, and add the environment variable `GOOGLE_API_KEY` with your key.
    *   Alternatively, for a more automated approach, you can use `firebase-tools` or `gcloud` CLI to set secrets, but for a single key, the console is straightforward.
    *   Firebase Functions also have `firebase functions:config:set yourservice.google_api_key="YOUR_KEY"`, but since modern Next.js on Firebase typically uses Cloud Run via `frameworksBackend`, managing env vars through Cloud Run console or `gcloud` is more direct. Check your `firebase.json` to see how it's configured.

4.  **Deploy**:
    ```bash
    firebase deploy
    ```
    This command will build your Next.js app (if not already built or configured to build during deploy) and deploy it to Firebase Hosting and the associated Cloud Run service.

5.  **Free Tier Considerations**:
    *   Firebase Hosting, Cloud Run, and Google AI (Gemini) all have free tiers.
    *   For low to moderate traffic, your app can often run for free.
    *   Monitor your usage in the Firebase and Google Cloud consoles. Costs will apply if you exceed free tier limits.
